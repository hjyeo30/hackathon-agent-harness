# 실패 원인 조사

## 관찰된 실패

- 요구사항/기대 결과:
- 관찰 결과와 최초 오류:
- 재현 명령 또는 조작 순서:
- 최소 입력 ID:
- 코드/빌드 상태와 실행 인스턴스:
- run ID / span ID / evidence 위치:
- 분류: 제품 / 검증 / 환경 / 아직 미확인

## 가설과 판별 실험

| 가설 | 왜 가능한가 | 한 가지 판별 실험 | 실제 결과 | 상태 |
|---|---|---|---|---|
| 예시: JOIN 중복 | 키가 유일하지 않음 | JOIN 전후 행 수·키 빈도 비교 | 실행 후 기록 | 지지/기각/미결 |

로그는 사건, 메트릭은 크기·시간·자원, 트레이스는 단계 순서를 보여준다.
셋을 모아도 원인이 자동 확정되지는 않는다. 입력→출력 경로의 첫 차이를 찾는다.
패치 횟수를 채우려고 시도하지 않고, 새 증거가 없는 반복은 조사 방식 변경을 알린다.

## 원인과 수정

확인된 원인과 추정만 가능한 부분을 분리한다. 가장 작은 수정, 바뀐 계약 여부,
사용자 결정이 필요한 부분을 적는다. 오류를 숨기는 fallback이나 assert 약화는 수정이 아니다.

## 수정 후 검증

원래 reproducer의 결과, 영향받는 회귀 검사, 새로 확인한 로그/메트릭/트레이스,
전후 조건이 동일한지 적는다. 관련 없는 전체 검사를 반복한 사실을 성과로 적지 않는다.

## 재발 방지와 한계

유지할 회귀 fixture/스크립트/지침 수정은 하나의 실제 실패에 연결한다.
아직 재현되지 않은 가능성과 미래 개선은 별도 보류한다.
