# 프로젝트 전용 검증 절차

실제 프로젝트를 읽고 실행해 채우는 문서다. 예제의 포트/셀렉터를 그대로 옮기지 않는다.

## 기능과 기준

- 요구사항 ID와 사용자 행동:
- 독립 oracle: 업무 규칙/손계산/작은 참조 알고리즘/레이블/rubric
- 입력 fixture와 선정 이유:
- 적용 전제: 순서/단위/허용 범위/상태 등

## Launch and doctor

실제 startup 명령, cwd, 필요한 설정(비밀 값 제외), 데이터 디렉터리, 포트/경로,
ready 판정, 코드/빌드 확인 방법을 적는다. 프로세스 생존과 서비스 준비를 구분한다.
공유 인스턴스를 사용하면 소유자를 기록하고 중복 실행하지 않는다.

## Drive and observe

| 사용자 행동/명령 | 관찰 위치 | 기대값 | 판정 |
|---|---|---|---|
| 실제 입력/클릭 | DOM/API/파일/DB | 독립적인 값/상태 | 실행 후 기록 |

HTTP 200, 성공 문구, 함수 호출 횟수만으로 업무 결과를 입증하지 않는다.
저장·다운로드가 요구되면 별도 읽기로 실제 결과를 확인한다. UI 미실행을 API 성공으로
바꾸지 않는다. mock 사용 경계와 실제 연결 범위를 적는다.

## Evidence

명령 argv, 시간, run/trace 식별, 입력 ID, 코드 fingerprint, stdout/stderr,
기대/관찰, 단위 있는 메트릭을 연결한다. 캡처/trace는 허용되는 환경에서만 저장한다.

## Failure and cleanup

문제가 생기면 먼저 instance/build/input이 맞는지 확인하고 최소 재현을 보존한다.
자신이 시작한 프로세스와 scratch만 정리한다. evidence를 cleanup으로 삭제하지 않는다.

## 유지와 사용자 인계

경로/레이블/schema/startup이 바뀌면 실제 다시 실행하고 절차를 고친다.
제품 회귀를 절차 수정으로 감추지 않는다. agent 검증과 user 확인을 따로 적는다.
