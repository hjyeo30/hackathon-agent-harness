# 사용자 확인 카드

## 지금 가능한 것

사용자 관점의 완결된 행동을 1–3문장으로 설명한다. 구현한 파일 목록으로 대체하지 않는다.

## 직접 확인

1. 접근할 실제 URL 또는 실행 명령.
2. 사용할 작은 입력.
3. 누를 버튼/선택할 항목/읽을 출력.
4. 보여야 할 구체적인 결과와 오류 정책.

예시: 작은 CSV를 올렸을 때 전체 수율 10.00%를 확인하고, 분모 0인 파일에는
명시적인 입력 오류가 표시되는지 본다. 실제 구현된 레이블과 경로로 바꿔 작성한다.

## AI가 확인한 것

검증 명령과 기대/관찰, 코드/입력 상태, evidence 위치, 남은 미검증을 짧게 적는다.
메인이 직접 사용한 경로를 구분한다. 사용자 확인 사실을 미리 작성하지 않는다.

## 판단 이유와 다음 묶음

중요한 선택 1–2개와 이유, 의도적으로 하지 않은 것, 다음 묶음 제안.
사용자에게 필요한 판단은 의미·우선순위·사용성에 한정하고 기술 로그를 읽게 떠넘기지 않는다.

## 확인 상태

기본: 사용자 확인 대기. 실제 피드백을 받은 뒤 반영 내용을 기록한다.
이미 전체 수행을 승인한 사용자의 범위를 이 카드 때문에 다시 승인 대기로 돌리지 않는다.
