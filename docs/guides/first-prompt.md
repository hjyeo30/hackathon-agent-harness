# 첫 프롬프트와 재개

## 준비 저장소를 처음 적용할 때

공개 URL을 실제 주소로 넣는다. 아직 없는 URL을 완성된 저장소처럼 안내하지 않는다.

> 이 공개 준비 저장소의 START_HERE.md를 읽고 현재 과제에 맞게 적용해줘.
> 현재 폴더의 README, 기존 지침, 코드와 데이터를 먼저 확인해.
> 나와 필수 조건·정답 기준·기능 묶음을 합의한 후 구현자와 검토자를 사용해.
> 각 묶음은 네가 직접 사용하고 검증한 뒤 내가 확인하게 해줘.

첫 응답은 거대한 작업 목록보다 요구사항 요약, 확인한 현재 상태, 중요한 결정 질문,
첫 성공 경로여야 한다. 설치나 모든 스킬 읽기를 프로젝트 이해의 대체물로 쓰지 않는다.

## 기존 프로젝트의 기능 추가

> 기존 CSV 조회 화면에 기간 필터를 추가해줘. 현재 업로드·다운로드를 유지해야 해.
> 기존 실행 경로부터 확인하고, 필터가 화면과 다운로드에 같이 적용되는지 계획해줘.

기대 동작: 기존 기동·검사를 먼저 확인, 필터 날짜의 포함/제외·시간대 의미를 질문,
UI/API/export 경계를 계획, 관련 회귀만 선택. 새 프레임워크로 교체하지 않는다.

## 데이터 분석 과제

> 이 CSV로 설비별 불량 현황을 설명해야 해. 어떤 계산이 맞는지부터 같이 정하자.

기대 동작: 열/단위/중복/분모/대상 기간과 데이터 품질 확인, 작은 손계산 입력,
집계→표/그림→설명 경로, 근거와 해석 한계. 요청하지 않은 웹앱은 만들지 않는다.

## 기존 실패 수정

> 다운로드 파일이 화면보다 한 행 적어. 재현하고 원인을 찾아 수정해줘.

기대 동작: 같은 입력에서 누락 확인, 파서/필터/페이지/CSV 변환 단계의 최초 차이,
최소 수정, 원래 재현 검사와 인접 회귀. 테스트를 10개씩 무작정 추가하지 않는다.

## 중단 후 재개

> issues의 현재 계획·진행·검증 기록을 읽고 이어가줘. 완료한 작업은 반복하지 말고,
> 마지막 코드 상태와 증거가 같은지 확인한 뒤 다음 필요한 작업을 알려줘.

현재 코드가 evidence 생성 후 바뀌었으면 영향받는 검증만 갱신한다. 기록의 PASS를
무조건 신뢰하거나 전체를 처음부터 재작성하지 않는다.
