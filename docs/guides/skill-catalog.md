# 스킬 선택 색인

모든 skill을 매번 읽지 않는다. 이름과 설명으로 선택하고 해당 본문과 필요한 참고만 읽는다.

| 상황 | 스킬 | 핵심 출력 |
|---|---|---|
| 새 과제에 kit 적용 | hackathon-start | 현황, 제약, 선택한 구성, 첫 질문 |
| 중요한 새 동작 설계 | frame-and-plan | 근거·결정·완료기준·묶음·관측 |
| 합의된 묶음 실행 | implement-chunk | 코드·실제 검사·증거·인계 |
| 계획/구현 독립 검토 | review-and-challenge | 재현 가능한 결함과 최소 수정 |
| 실제 결과 조작/확인 | verify-result | requirement별 기대/관찰/판정 |
| 원인 불명/반복 실패 | diagnose-failure | 최소 재현·가설·판별 결과·수정 증거 |
| 사용자 이해/복습 | recap | 실제 근거 기반 설명과 예상 질문 |

작은 오탈자 수정에 전체 계획/리뷰/도메인 절차를 돌리지 않는다. 일반 개발 요청에
recap을 자동 삽입하지 않는다. 복잡한 문제라도 필요하지 않은 전문가 역할을 늘리지 않는다.

## 스킬과 subagent의 차이

skill은 수행 방법이다. subagent는 독립 작업 컨텍스트와 역할이다. 메인도 verify-result를
사용하고, 구현자도 focused verification을 한다. 검토자가 있다는 이유로 구현자의
자체 검증이나 메인의 직접 사용이 면제되지 않는다. 이 중복은 서로 다른 책임이다.
같은 테스트를 아무 변경 없이 세 번 돌리는 것을 의미하지 않는다.
