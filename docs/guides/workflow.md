# 작업 흐름과 책임

## 시작과 합의

메인은 README·제출 조건·기존 코드/데이터를 읽고 문제를 자신의 말로 다시 설명한다.
사용자가 모를 도메인 고려사항을 구체적인 실패와 연결해 제시한다. 관찰 가능한 사실은
직접 조사하고 의미·우선순위는 사용자와 정한다. 계획은 가장 작은 완결된 흐름부터
구성한다. 예: CSV→집계→화면 한 경로, 또는 원자료→분석→근거 있는 결론 한 경로.

계획 합의 → 구현자 → 독립 검토자 → 메인의 직접 사용 → 사용자 확인 → 다음 묶음.
파일별 승인이나 모든 명령의 승인은 요구하지 않는다. 사용자가 전체 제작/검토/공개 등
구체적 범위를 일괄 승인한 경우 그 범위 안에서 끝까지 수행한다. 기존 승인을 지침이
임의로 취소하지 않는다. 새로운 업무 의미나 외부 권한을 요구하는 확장은 별도 결정이다.

## 역할

| 역할 | 소유하는 것 | 하지 않는 것 |
|---|---|---|
| 메인 | 사용자 대화, 근거/계획, 위임, 통합, 직접 사용, 최종 설명 | 구현자 보고를 그대로 완료 선언 |
| 구현자 | 지정한 코드/테스트/관측과 하나의 기능 묶음 | 다음 묶음 독단 착수, 재귀 위임 |
| 검토자 | 계획 전제·코드·실제 결과 비교, 반례, 증거 | 제품 소스나 기대값 변경, 가상의 결함 제조 |

역할 분리는 상시 병렬 실행을 뜻하지 않는다. 구현자는 한 명부터 시작한다. 독립적인
조사만 병렬화하고 공유 파일/브라우저/포트/데이터는 소유자를 정한다. read-only라는
역할 문장은 기술적 sandbox 보장이 아니다. 실제 Codex 권한은 부모 환경에서 확인한다.

## 상태를 섞지 않기

- 구현됨: 코드가 해당 동작을 포함한다.
- agent 검증됨: 정확한 입력·관찰·판정과 evidence가 있다.
- 사용자 확인됨: 사용자가 실제 결과를 확인하고 피드백했다.
- 차단됨/미검증: 필요한 조건 또는 검사가 아직 없다.

메인은 단순한 중계자가 아니다. 핵심 경로를 직접 한 번 실행하고 UI/API/데이터와
독립 정답을 읽는다. 사람이 읽을 설명에는 가능한 동작, 직접 확인법, 중요한 선택,
검증/미검증, 다음 묶음이 포함된다. 침묵은 사용자 확인으로 기록하지 않는다.

## 계획 변경과 종료

구현 중 더 좋은 private detail은 바꾸되 이유를 progress에 남긴다. 원래 계획을
사후 편집해 예정된 것처럼 만들지 않는다. 범위/공개 계약/업무 의미/큰 의존성이
변하면 사용자에게 영향을 설명한다. 선택 개선은 backlog에 두고 현재 필수 결과를 막지 않는다.

시간이 부족하면 필수 결과와 정답/저장/제출을 보호한다. 마지막에는 새 구조 변경보다
현재 파일 저장·경로·최신 실행 증거·한계를 확인한다. 후속 서술형은 사용자 본인의
이해가 필요하므로 작업 중 실제 선택과 결과를 설명하고, 허용 단계에서 recap을 제공한다.

## 180분 예시

0–20분 문제/환경, 20–35분 계획, 35–85분 첫 완결 흐름, 85–135분 필수 확장,
135–165분 회귀/경계/설명, 165–180분 제출 확인. 고정 시간표가 아니며 실제 과제
범위와 오류에 맞춰 조정한다. 사용자 확인 시간도 계획에 포함한다.
