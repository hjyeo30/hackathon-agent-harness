# 머신러닝 예측과 평가

## 질문과 기준선

예측 시점에 실제로 알 수 있는 입력인지, target의 의미와 잘못된 예측의 비용은 무엇인지
확인한다. 클래스 분포와 간단한 기준선을 먼저 본다. 모두 정상으로 예측하는 모델이
높은 accuracy를 얻을 수 있으므로 업무에 맞는 recall/precision/오류 개수도 본다.

학습/검증/최종 평가 분리 기준을 정한다. 같은 설비·배치·사람의 유사 샘플이 다른
분할에 섞이거나 미래 관측이 과거 예측 입력에 들어가는지 확인한다. 전처리의 fit도
학습 데이터에서 수행하고 평가 데이터에는 transform만 적용한다.

## 검증을 분리

- 파이프라인 정합성: 작은 데이터로 분할, 전처리, 예측 shape/ID 대응을 확인.
- 누수 검사: 평가 데이터가 학습/전처리 통계/threshold 선택에 사용되는지 조사.
- 모델 성능: 실제 사용 조건과 맞는 holdout/시간·그룹 분할에서 기준선 비교.
- 오류 해석: confusion counts와 실제 오분류 사례를 원자료와 함께 확인.
- 재현성: 입력/분할/설정/seed/라이브러리 환경을 기록. seed 하나가 일반화 증거는 아님.

같은 평가셋을 보고 반복 선택한 결과를 손대지 않은 독립 평가라고 부르지 않는다.
합성 데이터나 단위 테스트는 실제 모델 품질을 증명하지 않는다. 임의적인 정확도
threshold를 만들어 모델 성공으로 선언하지 않는다.

## 입력과 관측

극단적인 클래스 불균형, 한 클래스만 존재, 결측 열, 상수 열, 새로운 범주, schema 변화 중
실제 데이터 경계와 관련되는 경우를 고른다. 모든 모델에 같은 방어 코드를 넣지 않는다.
split→fit→predict→evaluate span, 분할별 수/클래스 분포, feature 목록/버전,
기준선·모델 지표와 단위/분모를 저장한다. 모델 파일만 남기고 평가 근거를 버리지 않는다.

[scikit-learn common pitfalls](https://scikit-learn.org/stable/common_pitfalls.html)는
전처리 불일치와 데이터 누수 사례를 설명한다.
