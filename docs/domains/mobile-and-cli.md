# 모바일과 터미널 프로그램

## 모바일

모바일 웹, 네이티브 앱, 하이브리드 중 무엇인지 확인한다. 실제 실행 가능한 기기/
에뮬레이터/시뮬레이터와 설치·디버그 권한을 먼저 확인한다. 브라우저 viewport를
줄인 검증으로 네이티브 권한·저장·백그라운드 동작을 확인했다고 하지 않는다.

실제 표면이 있을 때 Maestro 같은 도구를 선택한다. 없으면 그 경로는 BLOCKED/NOT RUN이며
검증된 것처럼 대체하지 않는다. 웹 과제에 모바일 환경을 미리 설치하지 않는다.

핵심 흐름, 입력/키보드 가림, 회전/복귀, 권한 거절, 오프라인 상태 중 실제 요구와
관련되는 것만 선택한다. 저장은 앱 재시작 후 확인할 필요가 있는지 계약에서 결정한다.
로그에는 device/runtime/build ID와 action→request→state 경로를 연결한다. 녹화/캡처는
허용될 때만 로컬 evidence에 보존한다.

## CLI/TUI

명령·인자·stdin·stdout·stderr·exit code·생성 파일이 사용자 인터페이스다.
비대화형 CLI는 subprocess, 대화형 도구는 PTY/Pexpect 같은 인터페이스를 고려한다.
사용자 입력을 shell 문자열로 조립하지 않는다. stdout의 machine-readable 출력과
stderr 진단을 구분하고 명령 실패를 성공 코드로 반환하지 않는다.

| 입력/상태 | 기대 관찰 |
|---|---|
| 정상 입력 | 정확한 출력과 파일 |
| 잘못된 인자/입력 | 비0 종료와 actionable error |
| 빈 입력 | 명시적 정책 |
| 공백/유니코드 경로 | 올바른 파일 처리 |
| 중간 취소/timeout | 자식 프로세스와 임시 파일 정리 |
| 같은 명령 재실행 | 정의된 덮어쓰기/중복/충돌 동작 |

진행 로그가 결과 JSON을 깨뜨리는지, 큰 출력으로 pipe가 막히는지, stderr를 놓치고
성공했다고 판단하는지 확인한다. 각 PTY 세션과 프로세스는 생성한 주체가 소유한다.
자신이 시작하지 않은 프로세스를 이름으로 일괄 종료하지 않는다.
