# 데이터 분석·CSV·SQL

## 원자료에서 시작

한 행의 의미, 키, 단위, 기간, 결측 표현, 숫자/문자 자료형, 중복 규칙을 확인한다.
미리 정리된 요약만 보지 말고 작은 원자료와 스키마를 읽는다. 파일 크기와 실제 메모리
사용은 다를 수 있다. 필요 열과 대표 표본을 먼저 조사한다.

사용자와 결정할 의미: 수율/불량률의 분모, 여러 배치 합치는 방식, 결측·중복의 처리,
기간과 대상 집단. invalid row를 조용히 삭제하고 성공 보고하지 않는다.
원본 보존, 정제 전후 개수와 제외 이유를 확인 가능하게 한다.

## 독립 oracle

9/10과 1/90의 전체 비율은 10/100. 배치 비율 평균과 다르다.
JOIN은 키 cardinality를 먼저 확인한다. many-to-one을 기대하는데 오른쪽 키가 중복이면
출력 행 수와 합계가 부풀 수 있다. DISTINCT를 무조건 붙여 의미를 숨기지 않는다.

| 검사 | 조건/입력 | 판정 |
|---|---|---|
| Golden | 손계산 가능한 2–5행 | 정확한 수치 |
| 보존 | 정제 전후/그룹별 행수와 합계 | 허용된 제외만 발생 |
| 중복 | 같은 키, 같은/다른 값 | 정한 중복 정책 |
| JOIN | 오른쪽 중복키·매칭 없음·NULL | cardinality/누락 계약 |
| 변형 | 행 순서 변경 또는 분할 집계 | 순서 무관/합성 가능한 연산에서 동일 |
| 경계 | 빈 결과·0 분모·극단값 | 정한 정책, 가짜 0 없음 |

부동소수점 허용오차는 문제 규모/단위에 맞게 정하고 임의로 크게 만들어 통과시키지 않는다.
시계열에 순서 불변을 적용하지 않는다. 날짜/문자 파싱 오류를 무시하지 않는다.

## 관측과 설명

read→validate→clean→join→aggregate→export 단계에 input/output rows, rejected count,
unique keys/groups, duration을 남긴다. 일부 중복/오류의 위치와 종류만 기록해 원인을 찾는다.
결과 표/그림의 단위·축·집계 기간이 코드와 같은지 직접 확인한다. 상관관계나 한 집단의
비교를 원인이나 전체 모집단의 사실로 과장하지 않는다. 분석 결론에도 데이터 근거가 필요하다.
