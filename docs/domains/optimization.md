# 일정·설비 배치·최적화

## 우선순위

feasible한 결과인지 먼저, 목적함수가 얼마나 좋은지는 그다음이다. 필수 제약과 선호를
나눈다: 설비 중복, 작업 선후행, 가용 시간, 용량, 정비 시간은 실제 문제에서 어떤
종류인지 확인한다. 목적함수 단위와 동률 처리·시간 경계도 명시한다.

작은 탐욕/기준선이 충분한지 확인한 뒤 복잡한 solver를 선택한다. 라이브러리 설치나
모델링 비용이 제한 시간에 맞는지 비교한다. “최적”이라는 표현은 증명/solver 상태가
뒷받침할 때만 쓰고 heuristic 결과는 feasible/best found로 설명한다.

## 생성기와 검증기 분리

생성된 일정과 원래 입력을 독립 검증기에 전달한다. 생성기의 내부 가정을 그대로
복사한 검사보다 interval 겹침, 선행 시간, 장비 용량 등을 직접 확인한다.

| 사례 | 검사 |
|---|---|
| 동일 설비 작업 겹침 | overlap 검출 |
| 끝나는 시각에 다음 작업 시작 | 경계 포함 규칙 |
| 선행 작업보다 먼저 시작 | precedence 위반 |
| 정비 구간 중 작업 | availability 위반 |
| 불가능한 입력 | infeasible을 명시, 임의 제약 완화 금지 |
| 동률·빈 작업 목록 | 합의한 결과/상태 |

고의로 겹친 일정이 validator를 통과하지 않는지 확인한다. 작은 문제는 완전 탐색
참조 결과와 비교할 수 있다. 큰 문제의 모든 최적해를 아는 척하지 않는다.

## 관측과 사용자 설명

parse→construct→improve→validate 단계, 작업/설비 수, 위반 건수, objective 값/단위,
경과 시간·종료 상태를 기록한다. 시각화는 실제 일정과 같은 입력을 사용한다.
좋아 보이는 Gantt 그림이 제약 통과의 증거는 아니다. 사용자에게 어떤 제약을 지켰고
어떤 품질/속도 tradeoff를 택했는지 설명한다.
