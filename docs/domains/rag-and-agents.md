# RAG·업무 Agent·도구 실행

## 요구사항을 둘로 나누기

답변이 맞는가와 도구가 올바른 상태 변화를 만들었는가는 다른 검사다.
검색 대상 문서/버전, 답변 근거, 근거가 없을 때의 행동, 허용된 도구·부작용을 정의한다.
불필요하게 외부 모델/API 키/유료 관측 서비스를 추가하지 않는다.

## RAG 검증

| 입력 | 관찰 | 판정 |
|---|---|---|
| 정답 문서가 있는 질문 | 검색 ID/원문/답변/인용 | 원문이 답변을 실제 지지 |
| 문서에 없는 질문 | 검색 결과와 답변 | 모른다고 표시, 추측을 사실로 만들지 않음 |
| 오래된 문서와 최신본 | 선택된 버전 | 과제의 최신성 정책 |
| 유사하지만 다른 항목 | 참조 대상 ID | 다른 설비/사람/제품 근거 혼동 없음 |
| 문서 안의 명령문 | 답변과 tool calls | 자료 내용이 시스템/사용자 지시를 대체하지 않음 |

문서 ID가 존재하는지만 확인하면 잘못된 인용도 통과한다. 선택된 문장과 주장 관계를
읽어야 한다. deterministic retrieval과 사실 fixture를 먼저 검사하고, 의미 평가가
필요하면 명확한 rubric과 사람 검토를 쓴다. 모델 점수 하나를 객관 정답으로 포장하지 않는다.

## 도구/상태 검증

동일 이벤트 반복, timeout 후 재시도, 도구 거절, 부분 실패, 종료 조건을 실제 계약에
맞게 확인한다. “등록했습니다”라는 답변보다 저장된 요청이 존재하고 중복이 없는지
별도 읽기로 확인한다. 실제 외부 부작용은 허용된 범위에서만, 연습은 로컬 fake tool로 한다.
로컬 fake 통과가 실 서비스 연결 성공이라는 주장은 하지 않는다.

## 관측

request/run ID, retrieval 문서 ID/version, tool call 이름/인자 요약, duration, status,
종료 이유와 최종 상태를 연결한다. 문서/비밀 전체를 외부 trace로 보내지 않는다.
retrieve→select→answer→grounding, 또는 decide→tool→persist→readback span을 구분한다.

평가셋은 정상/근거 없음/모호함/도구 오류를 필요한 만큼 포함한다. 실패 사례를 고친 뒤
해당 사례와 관련 회귀를 다시 확인하고 모든 질문을 무작정 반복하지 않는다.
