# 로컬 검색과 근거 검증 · RAG의 작은 기준선

이 예제는 **LLM을 호출하지 않는 단어 겹침 검색 + 원문 추출 기준선**이다. 전체 RAG나
의미 검색 품질을 입증하지 않는다. 외부 전송 없이 검색 결과와 최종 주장 연결을 연습한다.

## 계약과 실행

합성 SOP JSON의 최신 버전만 후보로 삼는다. query와 tag의 단어가 2개 이상 겹치고
단독 최고 점수인 경우만 원문을 반환한다. 없는 근거·동점은 명시적으로 답변을 보류한다.

```bash
python3 grounding.py 'pump pressure inspection'
python3 grounding.py 'wafer defect cause'
python3 -m unittest discover -s tests -v
```

첫 질문은 pump-pressure v2 원문, 둘째는 근거 부족을 반환해야 한다.
`.runs/grounding.json`에는 result, 검색 trace, 독립 grounding check가 남는다.
trace는 후보 수·최고 overlap·시간·trace_id를 담는다. 실제 query가 민감할 수 있으므로
무조건 원문 프롬프트를 로그에 저장하는 구조로 만들지 않았다.

## 무엇을 검사하는가

| 입력/고장 | 정답 기준 | 의미 |
|---|---|---|
| 알려진 질문 | v2 원문과 정확히 같은 답/인용 | 오래된 문서 채택 방지 |
| 모르는 질문 | abstain, 인용 없음 | 근거 없는 단정 방지 |
| 두 주제가 동점 | abstain | 임의 후보 선택 방지 |
| 답만 허위로 수정 | is_grounded=false | 있는 인용을 붙인 허위 주장 탐지 |
| citation 버전만 과거로 변경 | false | 인용 ID 존재만으로 통과시키는 오류 방지 |
| 같은 ID/version의 상충 내용 | 오류 | 최신본 선택이 모호한 데이터 거절 |

문서 속 문장은 실행 명령이 아니다. 이 프로그램은 문자열을 인용할 뿐 tool 실행 능력이 없다.
그렇지만 **원문 일치는 원문의 사실성·안전성·최신 운영 승인과 다르다.** 악성 문구를 그대로
인용할 수 있으며 이 테스트를 LLM prompt-injection 방어 검증이라고 부르면 안 된다.
실제 RAG에서는 자료의 신뢰도, 질문 적합성, 접근 권한, 모델의 인용 충실성을 따로 평가한다.

## 실패 분석과 확장 순서

1. 잘못된 답이면 검색된 ID/version과 점수를 확인한다.
2. 검색은 맞는데 답이 틀리면 생성/인용 연결 문제를 분리한다.
3. 근거가 없는 질문을 추가하고 abstain을 검사한다.
4. 검색 품질을 개선할 때 이 작은 golden suite를 회귀로 유지하되 별도 새 평가셋도 사용한다.

키워드 임계값은 이 fixture의 명시적 기준이며 일반 문제의 최적값이 아니다. 현장 설비 제어를
수행하지 않는다. recap에는 합성 SOP를 사용한 기준선이며 실제 설비 원인을 입증하지 않았다고 적는다.
