# 검증 발견 기록 — 2026-10-31

이 파일은 준비 저장소 제작 중 에이전트가 실제로 발견한 결함이다. 사용자가 직접
검사하거나 수정한 일로 표현하지 않는다. 환경은 macOS arm64, Python 3.9,
Node 24, Playwright Test 1.64.1, Chromium headless였다.

## 관찰과 원인

첫 브라우저 실행에서 네 검사 중 세 개가 통과하고 설비 필터 검사가 실패했다.
`getByLabel('설비', { exact: true }).selectOption('E2')`가 15초 후 timeout이었다.
서버 집계 실패가 아니었다. HTML label이 select를 감싸고 있어 option의 문자열도
접근성 이름에 포함되었고, 안정적인 정확한 이름으로 요소를 찾을 수 없었다.

## 수정과 재검증

제품 select에 명시적인 `aria-label="설비"`를 추가했다. 테스트를 느슨한 CSS selector로
바꾸거나 timeout을 늘리지 않았다. 실패한 설비 필터 검사를 다시 실행하여 통과했고,
E2=100%와 빈 기간 결과=`데이터 없음`을 확인했다.

Python HTTP 검사에는 추가로 aggregate 단계의 내부 예외를 주입했다. 응답은 500,
외부 메시지는 내부 정보 없이 확인 ID를 제공하고, 로컬 로그는 aggregate FAIL과
exception traceback을 남기는 것을 확인했다. Python 검사 8개가 통과했다.

처음 실패한 JSON report는 개발자의 로컬 `.runs/first-failure-report.json`으로 보존한다.
runtime report에는 로컬 경로 등이 있어 공개 Git에는 넣지 않는다. 최종 전체 실행 결과는
루트의 구현 진행/검토 기록을 따른다. 첫 실패 이후 일부 검사만 실행한 상태를
전체 최종 통과라고 바꾸어 쓰지 않는다.

## 독립 검토: 파일 교체 후 남은 설비 필터

독립 검토 에이전트가 여러 설비 CSV에서 E2를 선택한 뒤 E1만 있는 CSV로 바꾸면
첫 분석이 빈 결과이고 같은 분석을 한 번 더 누르면 90%가 되는 문제를 재현했다.
새 파일 요청에 이전 E2 필터가 남아 있었고, 응답 후 새 옵션 목록에는 E2가 없어
선택값이 빈 문자열로 바뀌었기 때문이다. 서버 계산 자체는 요청대로 동작했다.

해당 흐름을 실제 파일 업로드와 CSV 다운로드까지 포함한 브라우저 회귀 검사로 만들고
수정 전 실패(0 passed, 1 failed)를 확인했다. 파일 변경 시 설비 목록을 `전체 설비`로
초기화하도록 고친 뒤 같은 검사 1개가 통과했다. 기간 필터는 사용자가 설정한 값이므로
유지한다. 실패 report는 로컬 `.runs/file-replacement-failure-report.json`에 보존한다.
