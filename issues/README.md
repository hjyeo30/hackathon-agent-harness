# 과제 안의 작업 기록 공간

실제 문제의 기록은 응시 작업 환경 내부에 둔다. 공개 GitHub Issues나 외부 로그 서비스로
자동 전송하지 않는다. 이 공개 준비 레포에는 합성 예시와 템플릿만 포함한다.

여러 파일에 걸친 과제라면 `issues/001-short-name/` 아래 다음만 필요한 만큼 만든다.

- `implementation-plan.md`: 원래 합의 기준선.
- `implementation-progress.md`: 묶음별 결과, 판단 변경, 실행 증거, 사용자 피드백.
- `failure-<short-name>.md`: 원인 조사가 길거나 재현을 보존해야 할 때.
- `review.md`: 독립 검토와 지적 처리.
- `recap.md`: 사용자가 요청한 학습용 정리.

실행 로그는 runner가 생성한 run 디렉터리를 가리킨다. 긴 로그를 문서에 복제하지 않는다.
작은 단일 변경에는 별도 issue 폴더를 강제하지 않는다. 여러 파일의 같은 상태값을
수동으로 동기화하는 작업 관리 체계도 만들지 않는다.

예시 인계: “R2 다운로드 필터는 수정 완료. API 검사는 통과했지만 브라우저 다운로드는
미실행. 다음 에이전트는 progress의 현재 코드 상태와 마지막 run을 확인하고 해당
사용자 흐름을 실행한다.” 미실행을 완료로 복사하지 않는다.
